ICA Langflow Workflow Setup

Why ICA does nothing — and the exact steps to fix it right now.

The core problem: You have been calling the A2A endpoint — that is a chat interface. It talks to your agent but cannot execute workflows or generate artefacts. The Langflow workflow endpoint is what actually runs actions and returns structured output. You have never set it up.

The Two ICA Endpoints — and What Each Does

EndpointWhat it isWhat it returnsCan generate artefacts?
/agenticapps/a2a/… Agent chat (A2A). Sends a text message to your agent and gets a text reply. A conversation with messages[] NO — only chat text
langflow…/api/v1/run/<FLOW_ID> Langflow workflow execution. Actually runs your workflow and executes agents. Structured JSON output from your workflow YES — executes and returns

How the Correct Architecture Works

Your App → POST langflow…/api/v1/run/<FLOW_ID> → executes Langflow Workflow → calls Your ICA Agent → returns JSON Your App

The Langflow workflow is the bridge. Without it, nothing executes.

What You Need to Create

Two Langflow workflows inside your existing Agentic App:

#Workflow NameWhat it doesEnv var to set
1 notify-assignees Receives action plan → agent generates per-person notification email text → returns JSON with notifications array ICA_LANGFLOW_FLOW_ID_NOTIFY
2 generate-ica-assets Receives assessment data → agent generates Executive Summary, Client Email, Internal Email, Jira Epic, Slack message → returns JSON ICA_LANGFLOW_FLOW_ID_ASSETS

Step-by-Step: Create the Workflows

1

Open ICA Agent Studio

Go to https://agentstudio.servicesessentials.ibm.com

Log in → left nav → Agent & Assistant Studio → Get Started

2

Open your Agentic App

Under My Apps → find engagement-readiness-evaluator → click it

3

Go to Workflows tab → Create Workflow 1

Click Workflows tab → View All → Create Workflow

Name: notify-assignees   Description: Generates per-person task notification emails

Click Create → Langflow opens

4

Build Workflow 1 in Langflow (notify-assignees)

From the Components panel drag these 3 components onto the canvas:

  1. Chat Input — search "Chat Input" in components panel
  2. A2A Agent — expand ICA section → drag "A2A Agent"
  3. Chat Output — search "Chat Output" in components panel

Configure the A2A Agent component:

  • Click the Copy icon next to the Langflow title → paste into Agentic App ID field: 92690bf8-bb58-4b1e-9241-f8af02aa89ce
  • Select agent name: engagement-readiness-coordinator
  • Agent URL auto-populates

Connect the nodes:

  • Chat Input Message → A2A Agent Input
  • A2A Agent Response → Chat Output Text
5

Test Workflow 1 in Playground

Click Playground → paste this test message:

{"trigger_action":"notify-and-collect-acknowledgements","engagement_name":"Test","client_name":"Test Client","lead_consultant":"Fareena Akram","readiness_decision":"ready-with-conditions","readiness_score":72,"action_plan":[{"id":"action-01","title":"Engage Security team","ownerRole":"consultant","priority":"critical","dueLabel":"Before kickoff","instructions":"Contact security team","assigneeName":"Fareena Akram","assigneeEmail":"Fareena.Akram@ibm.com"}],"acknowledge_url":"https://example.com/api/task/update","status_url":"https://example.com/api/task/list","package_url":"https://example.com/api/ica-package/test"}

You should see the agent return a JSON object with a notifications array. If it returns a readiness report instead, check your agent's TRIAGE RULE 0 is deployed.

6

Get the Flow ID and API Key for Workflow 1

In Langflow (Workflow 1 open) → click Share (top right) → API access

You see a URL like:

https://langflow.servicesessentials.ibm.com/api/v1/run/xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx

Copy the UUID at the end — that is your FLOW_ID for NOTIFY

Click Generate API key → copy and save it securely

7

Create Workflow 2 (generate-ica-assets) — same steps

Back to Workflows tab → Create Workflow

Name: generate-ica-assets   Description: Generates 5 delivery artefacts after all tasks complete

Same Langflow layout: Chat Input → A2A Agent (same agent) → Chat Output

Test with:

{"trigger_action":"generate-ica-assets","engagement_name":"Test","client_name":"Test Client","lead_consultant":"Fareena Akram","readiness_decision":"ready-with-conditions","readiness_score":72,"confidence_score":80,"executive_summary":"Test summary","critical_issues":["Issue 1","Issue 2"],"recommendations":["Rec 1"],"open_questions":["Q1"],"risk_explanation":"Some risks","business_impact":"Some impact"}

Agent should return JSON with keys: executiveSummary, clientEmail, internalEmail, jiraEpic, slackMessage

Get the Flow ID from Share → API access (same API key works for both)

8

Update .env.local with your real values

ICA_LANGFLOW_FLOW_ID_NOTIFY=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
ICA_LANGFLOW_FLOW_ID_ASSETS=yyyyyyyy-yyyy-yyyy-yyyy-yyyyyyyyyyyy
ICA_LANGFLOW_API_KEY=your-langflow-api-key-here

Then restart your dev server: stop npm run dev → restart npm run dev

Next.js reads .env.local at startup — changes don't take effect until restart.

9

Verify the full flow works end to end

Run a full assessment → accept HITL → watch your terminal for:

[langflow] → POST https://langflow.servicesessentials.ibm.com/api/v1/run/<your-flow-id>
[langflow] ✓ workflow responded
[orchestrate/notify] Langflow ✓ | notifications=4

Then mark all tasks done in the app → watch for:

[task/update] ALL TASKS COMPLETE — triggering ICA delivery asset generation
[langflow] → POST https://langflow.servicesessentials.ibm.com/api/v1/run/<assets-flow-id>
[orchestrate/assets] Langflow ✓ | assets=parsed
[task/update] Delivery asset emails: 5/5 sent

After Setup: What ICA Will Do Automatically

TriggerICA doesApp then does
Consultant clicks Accept (HITL) Workflow 1 runs → agent generates notification email text for each assignee Sends ICA-authored emails to each person with their tasks
All tasks marked complete Workflow 2 runs → agent generates Executive Summary, Client Email, Internal Email, Jira Epic, Slack message Emails consultant (exec summary + internal email + Jira epic + Slack draft), emails client (client email)
Important note on URL format: The documentation says if the generated URL contains agentstudio, replace it with langflow. Your Flow ID URL should always start with https://langflow.servicesessentials.ibm.com/api/v1/run/
If Workflow test shows wrong output: Your agent's YAML may not be deployed. Go to ICA Agent Studio → your app → Agents tab → click your agent → Upload/Update the YAML from agent-orchestration-creation.yaml in your project. The TRIAGE RULE 0 that recognises trigger_action must be active.

Troubleshooting

ErrorCauseFix
401 on Langflow call Wrong or expired API key Regenerate from Share → API access → update ICA_LANGFLOW_API_KEY
404 on Langflow call Wrong Flow ID Re-copy from Share → API access URL (UUID after /run/)
Agent returns readiness report instead of notifications JSON YAML TRIAGE RULE 0 not deployed to agent Upload agent-orchestration-creation.yaml to Agent Studio
Assets not parsed (no JSON in response) Agent returned prose instead of JSON Check Playground output — if agent wraps in markdown, add "Return compact JSON only, no code fences" to system prompt
Server still calls A2A instead of Langflow ICA_LANGFLOW_FLOW_ID_* not set or server not restarted Fill in the vars in .env.local → restart npm run dev
